# Deploying Prahari: Render (API + Postgres) and Vercel (frontend)

The API and its database run on Render's free tier from `render.yaml`; the frontend is a static Vite build on Vercel that calls the API directly over CORS.

## 1. Push the repository to GitHub

Both hosts deploy from GitHub. Commit, push to `main`.

## 2. Backend on Render

1. Render dashboard → **New → Blueprint** → pick this repository. Render reads `render.yaml` and proposes a database `prahari-db` and a web service `prahari-api`, both free, both in Singapore.
2. Fill in the three prompted values:
   - `PRAHARI_LEAD_PASSWORD`: password for `meow` (lead)
   - `PRAHARI_ANALYST_PASSWORD`: password for `analyst`
   - `PRAHARI_CORS_ORIGINS`: leave as `https://placeholder.invalid` for now; set it in step 4
3. Apply. The first build takes a few minutes. When the service is live, open `https://<service>.onrender.com/healthz`; it answers `{"status":"ok"}`. The first boot seeds the seed-42 demo, its evaluation and the adversary bench (about 15 s).

## 3. Frontend on Vercel

1. Vercel → **Add New → Project** → import this repository.
2. **Root Directory:** `frontend`. Framework is detected as Vite; `frontend/vercel.json` sets the rest.
3. **Environment variable:** `VITE_API_BASE` = `https://<service>.onrender.com` (no trailing slash). It is read at build time, so redeploy after changing it.
4. Deploy and note the production URL, e.g. `https://prahari.vercel.app`.

## 4. Connect them

In Render → `prahari-api` → Environment, set

```
PRAHARI_CORS_ORIGINS=https://prahari.vercel.app,https://prahari-*.vercel.app
```

The second entry admits Vercel preview deployments; one `*` matches letters, digits and hyphens only. Saving restarts the service. Sign in at the Vercel URL with `meow` and your lead password.

## What the free tier means

| Fact | Effect | What Prahari does about it |
|---|---|---|
| The service sleeps after 15 min idle | First request takes up to a minute | The sign-in page says so after 4 s; the live stream reconnects on its own |
| Local disk is wiped on every restart | Files do not survive | Everything, including ground truth for evaluation, is in Postgres |
| Free Postgres expires after 30 days | The database is deleted | Upgrade the database plan before then, or recreate it and the demo reseeds |
| Free Postgres holds 1 GB | Each adversary campaign stores five mutated datasets | Plenty for the demo; watch usage if you run hundreds of campaigns |
| One instance | No horizontal scaling | The event stream uses Postgres LISTEN/NOTIFY, so scaling out later needs no code change |

## Secrets

- `PRAHARI_JWT_SECRET` is generated by Render once and kept, so sign-ins survive restarts. Rotating it signs everyone out.
- With both passwords set, the published demo passwords (`prahari-lead`, `prahari-analyst`) are refused, and passwords you supply are never written to the logs.
- Changing a password in Render's environment takes effect on the next restart.
